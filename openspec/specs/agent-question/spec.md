# agent-question Specification

## Purpose
AI の問いをユーザーへ示し、その回答を受け取る往復そのものを、置き場所から切り離して規定する。質疑応答をさせたい画面はこの機構を置くだけでよく、問いの見え方・答え方・待ち方は画面によって変わらない。

## Requirements

### Requirement: 問いは置かれた画面の上にオーバーレイで開く

システムは問いを、置かれた画面の上に重なる面として開く SHALL。ユーザーを別の画面へ移してはならない。面が開いている間、背後の画面は操作を受け付けない。

#### Scenario: 問いが届く

- **WHEN** 質疑応答の機構が置かれた画面を開いているユーザーに、AI の問いが届く
- **THEN** その画面を離れないまま、上に重なる面で問いが示される

#### Scenario: 背後をさわろうとする

- **WHEN** 問いの面が開いている状態で、ユーザーが背後の画面を操作しようとする
- **THEN** 背後の画面は操作を受け付けない

### Requirement: 問いの見え方は画面によって変わらない

システムは問いを、話題タグ・詳細説明・問い本文・選択肢とその説明・自由入力欄の順で示す SHALL。推奨がある選択肢にはその印を付ける。この並びと構成は、機構を置いた画面がどれであっても同じとする。

#### Scenario: 問いが示される

- **WHEN** 問いの面が開く
- **THEN** 話題タグ・詳細説明・問い本文・選択肢とその説明・自由入力欄が、この順で示される

#### Scenario: 推奨がある

- **WHEN** 問いの選択肢のうち1つが推奨である
- **THEN** その選択肢に推奨であることの印が付く

#### Scenario: 別の画面で同じ問いを受ける

- **WHEN** 別の画面に置かれた同じ機構が問いを受ける
- **THEN** 並びも構成も、先の画面と同じ形で示される

### Requirement: 回答は選択肢か自由入力のどちらか一方

システムはユーザーの回答を、選択肢を選んだものと自分の言葉で書いたもののどちらか一方として受け取る SHALL。選択肢は決定を代行する仕掛けではないため、自由入力欄は選択肢と同時に常に示す。どちらも与えられていない状態では送れず、回答が必要であることを示す。

#### Scenario: 選択肢を選んで送る

- **WHEN** ユーザーが選択肢を1つ選んで送る
- **THEN** その選択肢を選んだこととして回答が受け取られる

#### Scenario: 自分の言葉で書いて送る

- **WHEN** ユーザーが自由入力欄に書いて送る
- **THEN** 書いた内容が回答として受け取られ、選択肢を選んだ扱いにはならない

#### Scenario: どちらも無いまま送ろうとする

- **WHEN** 選択肢を選ばず、自由入力欄も空のまま送ろうとする
- **THEN** システムは送らず、回答が必要であることを示す

### Requirement: 面は回答するまで閉じない

システムは、問いに答え終わるまで問いの面を閉じさせない SHALL。答えずに閉じて問いを見失う経路を作らない。面を閉じるのは、AI が問いを打ち止めたときとする。

#### Scenario: 答えずに閉じようとする

- **WHEN** 問いの面が開いている状態で、ユーザーが答えずに面を閉じようとする
- **THEN** 面は閉じず、問いは示されたまま残る

#### Scenario: 問いが尽きる

- **WHEN** AI が問いを打ち止める
- **THEN** 面は閉じ、置かれた画面の本来の表示に戻る

### Requirement: 次を待つ間の待機は面の中で示す

システムは回答を送ってから次が返るまでの間、待機していることを面の中で示す SHALL。待機中は追加の送信を受け付けない。待機表示の文言は場面ごとに規定し、機構を置いた側が与える。

#### Scenario: 回答を送った直後

- **WHEN** ユーザーが回答を送る
- **THEN** 面は開いたまま、その中で待機していることが示され、続けて送ることはできない

#### Scenario: 次の問いが返る

- **WHEN** 次の問いが返る
- **THEN** 待機の表示は終わり、同じ面に次の問いが現れる

### Requirement: 書きかけは次の問いへ持ち越さない

システムは問いが次に置き換わったとき、選択と自由入力欄の書きかけを空に戻す SHALL。前の問いへの入力が次の問いの回答として送られてはならない。

#### Scenario: 次の問いが現れる

- **WHEN** 回答を送り、同じ面に次の問いが現れる
- **THEN** 選択は外れ、自由入力欄は空になっている

### Requirement: 送れなかった回答は同じ問いのまま送り直せる

システムは回答を送れなかったとき、および AI から応答が得られなかったとき、その旨を示したうえで同じ問いに答え直せる状態に戻す SHALL。問いを失わせてはならない。

回答が受け取られたうえで、AI が前の応答をまだ返していない場合は、これに当たらない SHALL。そのときシステムは失敗を示してはならない（MUST NOT）。待機として示し、ユーザーに同じ問いへ答え直させてはならない（MUST NOT）。

#### Scenario: 回答が送れない

- **WHEN** 回答の送信が失敗する
- **THEN** 送れなかったことが示され、同じ問いに対してもう一度送れる

#### Scenario: AI から応答が得られない

- **WHEN** 回答は届いたが、AI から応答が得られない
- **THEN** 応答が得られなかったことが示され、面は開いたまま同じ問いに対してもう一度送れる

#### Scenario: 前の応答をまだ待っている

- **WHEN** 回答は受け取られたが、AI が前の応答をまだ返していない
- **THEN** 失敗は示されず、待機していることが面の中で示される。ユーザーは何もせずに次の問いを待てる

#### Scenario: 待っている間に次が返る

- **WHEN** 前の応答を待っている状態で、AI が次の問いを返す
- **THEN** 待機の表示は終わり、同じ面に次の問いが現れる。同じ問いへの回答が二重に記録されることはない

### Requirement: 設定を1つも書かずに使える

機構は、受け取る設定の名前と既定値を公開しなければならない（SHALL）。

機構を置く側は、設定を1つも書かずに機構を使えなければならない（SHALL）。既定値のままで、問いが届いて示され、回答を送れ、次が返るまで待てること。

#### Scenario: 設定を書かずに置く

- **WHEN** 置く側が設定を1つも書かずに機構を入れ、質疑応答をさせたい画面に置く
- **THEN** 問いが届いて示され、回答が送られ、次が返るまで待機が面の中で示される

#### Scenario: 設定を変える

- **WHEN** 置く側が公開された設定の名前で値を書く
- **THEN** その値が効く。機構の中のファイルを書き換える必要は無い

### Requirement: 往復の接続先は機構が既定で持つ

機構は、問いを受ける先・回答を送る先・次を待つ間に状態を確かめる先を、既定の接続先として持たなければならない（SHALL）。置く側が画面ごとに接続先を書く必要があってはならない（MUST NOT）——画面ごとに書く形にすると、書き忘れた画面で問いが届かず回答も送れない状態が、合図なしに生まれる。

置く側が公開された設定で接続先を変えたときは、問いの受信・回答の送信・待機中の確認のすべてがその先へ向かなければならない（SHALL）。一部だけが元の先に残ってはならない（MUST NOT）。

#### Scenario: 既定の接続先で往復する

- **WHEN** 置く側が接続先を書かずに機構を置く
- **THEN** 問いが届き、回答が送られ、次が返るまで待てる。画面側のファイルに接続先は現れない

#### Scenario: 接続先を変える

- **WHEN** 置く側が公開された設定で接続先を変える
- **THEN** 問いの受信・回答の送信・待機中の確認がすべて新しい先へ向く。画面側のファイルは変わらない

### Requirement: 面の見た目は1行の取り込みで効く

機構が持つ面の見た目（待機の点滅・詳細説明の面・選択肢・未入力の知らせ）は、置く側が**1行の取り込み**だけで有効にできなければならない（SHALL）。

置く側に、機構の中のファイルを指す path を書かせてはならない（MUST NOT）——機構の実体は置く側のリポジトリの外に在り、相対 path は当たらない。

機構の中だけで使われている見た目も、置く側が取り込みの1行のほかに手続きを足さずに、ビルド後に効かなければならない（SHALL）。

#### Scenario: 見た目を取り込む

- **WHEN** 置く側が機構の見た目を1行で取り込む
- **THEN** 待機の点滅・詳細説明の面・選択肢・未入力の知らせが、機構の定めた見た目で示される。ほかに書く行は無い

#### Scenario: 機構の中だけで使われている見た目

- **GIVEN** 機構の中だけで使われている見た目がある
- **WHEN** 置く側がアプリをビルドする
- **THEN** その見た目はビルド後も効いている。置く側が手続きを足す必要は無い

### Requirement: 置く側の theme の上書きを打ち消さない

面のうち置く側の UI の部品で組まれている箇所（話題タグ・自由入力欄・送信ボタン）について、置く側がその側の UI の theme で見た目を上書きしたとき、その上書きは面に効かなければならない（SHALL）。機構が自前で持つ見た目の指定が、置く側の上書きを打ち消してはならない（MUST NOT）。

#### Scenario: 置く側が部品の見た目を上書きする

- **WHEN** 置く側がその側の UI の theme で、自由入力欄と送信ボタンの見た目を上書きする
- **THEN** その上書きが面に効く。機構の自前の指定に打ち消されない
